Архітектурний опис системи бронювання квитків

1. Вступ та опис предметної області

Система бронювання квитків призначена для автоматизації процесу пошуку подій, вибору вільних місць, оформлення та оплати квитків користувачами. Предметна область охоплює взаємодію між клієнтами, каталогом подій, платіжним шлюзом та адміністраторами системи. Користувач може переглядати доступні сеанси, створювати бронювання та отримувати електронні квитки після успішної оплати. Система забезпечує актуальність даних про наявність вільних місць у реальному часі та запобігає конфліктам подвійного бронювання.

2. Архітектурний підхід

Для розробки обрано шарову архітектуру (Layered Architecture) у поєднанні з клієннт-серверним підходом. Такий розподіл дозволяє чітко відокремити інтерфейс користувача від бізнес-логіки та рівня збереження даних, що підвищує підтримку та масштабованість проєкту.

3. UML Class Diagram (Структура класів)

Нижче наведено опис основних класів системи та зв'язків між ними:

User (Користувач): базовий клас із атрибутами userId, name, email. Має метод login().

Customer (Клієнт): спадкується від User, містить специфічний метод bookTicket().

Event (Подія): описує захід (eventId, title, date, price). Методи: getDetails().

Ticket (Квиток): представляє куплене місце (ticketId, seatNumber, status). Методи: validate().

Booking (Бронювання): керує процесом замовлення (bookingId, status). Методи: createBooking(), cancelBooking().

Зв'язки:

Наслідування: Customer наслідує User.

Асоціація: Customer пов'язаний із Booking.

Композиція: Booking містить сутності Ticket (квиток не існує окремо від бронювання).

Агрегація: Event містить перелік доступних квитків.

4. UML Component Diagram (Архітектурні шари)

Система поділена на три основні шари:

Presentation Layer (Клієнтський шар): інтерфейс користувача (Web/Mobile UI), який відповідає за відображення даних та збір введеної інформації.

Business Logic Layer (Шар бізнес-логіки): сервіси та компоненти обробки замовлень, перевірки доступності місць та взаємодії з оплатою.

Data Access Layer (Шар доступу до даних): репозиторії та драйвери для збереження інформації у базі даних.

Взаємодія: Presentation звертається до Business Logic, який своєю чергою використовує Data Access для збереження чи читання даних.
